# Cyclone Damage Impact Viewer

A Next.js and Flask application for visualizing cyclone damage impact on an interactive Google Map.

The application currently supports three cyclones:

- Fani
- Biparjoy
- Tauktae

Vayu is intentionally excluded because it did not make landfall.

## How It Works

The application has two parts:

- **Next.js frontend**: renders the Google Map, cyclone selector, cloud overlay, loading state, errors, and predicted heatmap.
- **Flask backend**: loads the trained PyTorch model and exposes the cyclone catalog and prediction endpoint.
- **Prediction model**: lives in `backend/Prediction-api/` and predicts cyclone intensity and wind radii from satellite and ERA5 data.
- **Damage calculations**: `backend/Prediction-api/Damage.py` contains the grid, wind-field, elevation, population, and damage-index calculations used by the standalone prediction workflow.

When a cyclone is selected:

1. The frontend sends the cyclone ID and center coordinates to Flask.
2. Flask imports `backend/Prediction-api/test.py`.
3. `test.py` selects the correct satellite frame and ERA5 data for that cyclone.
4. The PyTorch model predicts values such as maximum wind, pressure, and wind radii.
5. The predicted `r34avg` radius is converted from nautical miles to meters.
6. The map zooms to the affected grid and displays a heatmap centered on the cyclone.

The model predicts cyclone intensity and radius. It does not predict a new latitude or longitude, so each cyclone uses its configured center.

## Requirements

- Windows, macOS, or Linux
- Python 3.10 or newer
- Node.js and npm
- A Google Maps JavaScript API key
- PyTorch and the scientific Python dependencies
- The trained model checkpoint and prediction data files

## Python Setup

Install the backend and model dependencies from the backend directory:

```powershell
cd backend
py -m pip install -r requirements.txt
```

`torch` is the package name for PyTorch. The project uses `matplotlib`, not `matpoilt`.

Verify the main imports:

```powershell
py -c "import flask, torch, pandas, numpy, xarray, matplotlib; print('Python dependencies OK')"
```

If PyTorch is installed with CUDA support, the model uses CUDA automatically. Otherwise it falls back to CPU.

## Model Files

The prediction endpoint expects this checkpoint:

```text
backend/Prediction-api/runs/india_finetune/best_model_finetuned.pt
```

It also expects the satellite, ERA5, and normalization data referenced by `backend/Prediction-api/test.py` and `backend/Prediction-api/predict.py`.

If the checkpoint is missing, `/api/predict` returns HTTP `503` with a message explaining where the file must be placed. The checkpoint is not generated by `npm run build`.

## Google Maps Setup

Copy the environment template:

```powershell
Copy-Item .env.example .env.local
```

Set the browser-restricted Google Maps key in `.env.local`:

```env
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=YOUR_GOOGLE_MAPS_BROWSER_KEY
```

Optional cloud tiles require an OpenWeather map key:

```env
NEXT_PUBLIC_WEATHER_MAP_API_KEY=YOUR_OPENWEATHER_KEY
```

`NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID` is optional. The application omits it when empty, so a valid Map ID is not required for the basic map.

Enable the following Google Cloud services for the browser key:

- Maps JavaScript API
- Places API is not required by the current cyclone-only UI

Restrict the API key to your local and production web origins.

## Run the Application

Start Flask in one terminal:

```powershell
cd backend
py app.py
```

Flask runs on:

```text
http://127.0.0.1:5000
```

Start Next.js in a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open:

```text
http://localhost:3000
```

The Next.js rewrite in `frontend/next.config.js` proxies `/api/*` requests to Flask. Locally it uses
`http://127.0.0.1:5000` by default. Set `FLASK_API_URL` when the Flask server is hosted elsewhere.

## Deploying to Vercel

Vercel is suitable for the Next.js frontend, but the Flask server and PyTorch model should be hosted separately. The model checkpoint and scientific data files are large and are not a good fit for a Vercel deployment.

### 1. Deploy the Flask backend

Deploy the `backend/` directory to a Python-capable host such as Render, Railway, Fly.io, or a VM. Configure its start command as:

```bash
gunicorn app:app
```

Use a persistent service with enough memory for PyTorch and the model checkpoint. Install the backend dependencies from `requirements.txt`, which includes:

```text
gunicorn
```

Make sure the deployed backend responds successfully at:

```text
https://YOUR-BACKEND-DOMAIN/health
```

### 2. Import the project into Vercel

1. Push the project to GitHub.
2. In Vercel, choose **Add New Project** and import the repository.
3. Keep the framework preset as **Next.js**.
4. Set Vercel's **Root Directory** to `frontend`.
5. Use `npm run build` as the build command if Vercel does not detect it automatically.
6. Leave the output directory on the default Next.js setting.

### 3. Add Vercel environment variables

Add these variables in the Vercel project settings for Production, Preview, and Development as appropriate:

```env
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=YOUR_GOOGLE_MAPS_BROWSER_KEY
NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID=YOUR_MAP_ID_OR_LEAVE_EMPTY
NEXT_PUBLIC_WEATHER_MAP_API_KEY=YOUR_OPENWEATHER_KEY
FLASK_API_URL=https://YOUR-BACKEND-DOMAIN
```

`FLASK_API_URL` must not end with `/api`; the Next.js rewrite appends `/api/cyclones` and `/api/predict` automatically.

### 4. Configure CORS and API keys

The Flask service currently enables CORS. Restrict the Google Maps browser key to the Vercel domain after deployment, for example:

```text
https://your-project.vercel.app/*
```

Redeploy after changing Vercel environment variables.

### Important Vercel limitation

Do not expect the PyTorch model to run inside a normal Vercel frontend deployment. The Vercel app forwards prediction requests to the separately hosted Flask service, which must contain:

```text
backend/Prediction-api/runs/india_finetune/best_model_finetuned.pt
backend/Prediction-api/data/
```

The model must be installed and loaded by the backend service.

## Using the App

1. Start both Flask and Next.js.
2. Open `http://localhost:3000`.
3. Choose Fani, Biparjoy, or Tauktae from the blue cyclone selector.
4. Wait for the `Calculating damage heatmap...` status to finish.
5. The map zooms to the cyclone's affected area.
6. The predicted damage heatmap appears around the cyclone center.
7. Use Google Maps controls to pan, zoom, change map type, open Street View, or enter fullscreen mode.
8. Toggle cloud tiles from the Clouds control if an OpenWeather key is configured.

## API Endpoints

### Health check

```http
GET /health
```

Example response:

```json
{
  "status": "ok"
}
```

### List cyclones

```http
GET /api/cyclones
```

The current centers are:

```json
[
  { "id": "FANI", "name": "Fani", "center": { "lat": 19.78, "lon": 85.81 } },
  { "id": "BIPARJOY", "name": "Biparjoy", "center": { "lat": 23.21, "lon": 68.61 } },
  { "id": "TAUKTAE", "name": "Tauktae", "center": { "lat": 20.82, "lon": 71.03 } }
]
```

### Run a prediction

```http
POST /api/predict
Content-Type: application/json
```

Request:

```json
{
  "cyclone": "FANI",
  "center": {
    "lat": 19.78,
    "lon": 85.81
  }
}
```

A successful response includes:

- `cyclone`: selected cyclone ID
- `center`: heatmap center
- `radius_meters`: predicted 34-knot wind radius in meters
- `radius_nautical_miles`: original model radius
- `intensity`: model outputs such as `vmax`, `mslp`, `r34avg`, `rmw`, `r50avg`, and `r64avg`
- `grid`: affected-area limits used for map zooming

## Troubleshooting

### `py app.py` fails immediately

Check that Flask is installed:

```powershell
py -m pip install flask flask-cors
```

### Prediction returns `Model checkpoint not found`

Place the trained file at:

```text
backend/Prediction-api/runs/india_finetune/best_model_finetuned.pt
```

### Prediction returns `No module named torch`

Install PyTorch:

```powershell
py -m pip install torch
```

### The cyclone list loads but prediction fails

Check the Flask terminal. The model may be missing one of its satellite, ERA5, CSV, Excel, or normalization files.

### The map reports a Google Map ID configuration error

Remove or correct `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID` in `.env.local`, then restart Next.js. The basic map works without a Map ID.

### Heatmap does not appear

Check that:

- Flask is running on port `5000`.
- Next.js is running on port `3000`.
- The model checkpoint exists.
- PyTorch and model dependencies are installed.
- The browser console and Flask terminal contain no prediction errors.
